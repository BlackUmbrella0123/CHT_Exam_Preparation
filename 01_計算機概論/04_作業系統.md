## 觀念 1：作業系統的角色與類型

### 1.1 OS 的主要功能
行程管理、記憶體管理、檔案系統管理、I/O 裝置管理、保護與安全、提供使用者介面。

### 1.2 雙模式運作
- **使用者模式（User mode）** 與 **核心模式（Kernel mode）**，由模式位元區分。
- 使用者程式要求 OS 服務 → 透過 **系統呼叫（System Call）** 切換到核心模式（例：`open()`、`read()`、`fork()`）。
- **特權指令**（例：I/O 指令、關中斷、修改計時器）只能在核心模式執行。

### 1.3 系統類型
| 類型 | 特色 |
|---|---|
| 批次處理 | 工作集中整批處理，無互動 |
| 多元程式 | 記憶體同時放多個程式，CPU 閒置時切換，提高使用率 |
| **分時系統** | 時間片輪流，給使用者「獨占」的錯覺，重視**回應時間** |
| **即時系統** | 必須在**期限內**完成；硬即時（飛控、醫療）vs 軟即時（影音串流） |
| 分散式系統 | 多台電腦透過網路合作 |

### 1.4 核心架構
- **單體式核心（Monolithic）**：所有服務在核心中，效率高（傳統 UNIX、Linux）。
- **微核心（Microkernel）**：核心只留最基本功能，其他移到使用者空間，穩定、易擴充，但訊息傳遞成本高。

## 觀念 2：行程與執行緒

### 2.1 行程（Process）＝執行中的程式
記憶體配置：**Text（程式碼）、Data（全域變數）、Heap（動態配置，往上長）、Stack（區域變數、函式呼叫，往下長）**。

### 2.2 行程狀態
```
New ──允入──▶ Ready ──分派(dispatch)──▶ Running ──結束──▶ Terminated
                ▲  ◀──中斷/時間到──────────┘   │
                │                              │ 等待 I/O 或事件
                └──────I/O 完成────── Waiting ◀┘
```
- **Running → Ready**：時間片用完或被搶占
- **Running → Waiting**：等待 I/O
- **Waiting → Ready**：I/O 完成（注意：不會直接回到 Running）

### 2.3 PCB 與內容切換
- **PCB（行程控制區塊）**：記錄行程狀態、PC、暫存器、排程資訊、記憶體資訊、開啟的檔案等。
- **內容切換（Context Switch）**：保存舊行程 PCB、載入新行程 PCB；切換期間沒有做有用的工作（純額外負擔）。

### 2.4 執行緒（Thread）
| 同一行程內的執行緒**共享** | 每個執行緒**獨有** |
|---|---|
| 程式碼、全域資料、Heap、開啟的檔案 | **Stack、暫存器、PC**、執行緒 ID |

優點：建立與切換成本比行程低、回應性好、資源共享、可利用多核心。

### 2.5 fork()
`fork()` 複製出子行程；**父行程回傳子行程 PID，子行程回傳 0**，失敗回傳 −1。
連續呼叫 n 次 `fork()` 會產生 **2ⁿ** 個行程（含原本的）。

## 觀念 3：CPU 排程

### 3.1 名詞
- **等待時間** = 完成時間 − 到達時間 − 執行時間（burst）
- **周轉時間（Turnaround）** = 完成時間 − 到達時間
- **回應時間** = 第一次取得 CPU 的時間 − 到達時間
- **搶占式（Preemptive）**：執行中可被打斷；**非搶占式**：執行到結束或自行讓出。

### 3.2 演算法比較
| 演算法 | 搶占？ | 特色 |
|---|---|---|
| **FCFS** | 否 | 簡單；**護航效應（Convoy Effect）**：短工作卡在長工作後面 |
| **SJF** | 否 | 平均等待時間**最小**（非搶占中最佳）；會**飢餓** |
| **SRTF**（搶占式 SJF） | 是 | 新工作剩餘時間更短就搶占；平均等待時間理論最佳 |
| **Priority** | 皆可 | 低優先權可能**飢餓** → 用 **老化（Aging）** 解決 |
| **RR**（輪流） | 是 | 時間片 q；適合分時系統；q 太大 → 退化成 FCFS，q 太小 → 內容切換過多 |
| 多層佇列 / 多層回饋佇列 | 是 | 多層回饋可讓行程在佇列間移動，最有彈性 |

### 3.3 範例：P1=24、P2=3、P3=3，同時在時間 0 到達（順序 P1、P2、P3）

**FCFS**
```
| P1                     | P2 | P3 |
0                        24   27   30
```
等待：P1=0、P2=24、P3=27 → 平均 **17**

**SJF**
```
| P2 | P3 | P1                     |
0    3    6                        30
```
等待：P2=0、P3=3、P1=6 → 平均 **3**

**RR（q = 4）**
```
| P1 | P2 | P3 | P1 | P1 | P1 | P1 | P1 |
0    4    7    10   14   18   22   26   30
```
等待：P1 = 30 − 24 = 6、P2 = 4、P3 = 7 → 平均 **17/3 ≈ 5.67**

## 觀念 4：行程同步

### 4.1 競爭條件與臨界區
- **競爭條件（Race Condition）**：多個行程同時存取共享資料，結果取決於執行順序。
- **臨界區（Critical Section）** 解法須滿足三條件：
  1. **互斥（Mutual Exclusion）**：同時最多一個進入
  2. **進行（Progress）**：沒人在臨界區時，不能無限延後想進入者的決定
  3. **有限等待（Bounded Waiting）**：等待次數有上限，不會飢餓

### 4.2 號誌（Semaphore）
```c
wait(S)   / P(S):  S--; if (S < 0) 阻塞此行程;
signal(S) / V(S):  S++; if (S <= 0) 喚醒一個等待中的行程;
```
- **二元號誌（Mutex）**：值 0 或 1，用來互斥。
- **計數號誌**：初值 = 可用資源數量。
- 在上述實作中，**S 為負時，|S| = 正在等待的行程數**。

### 4.3 經典問題
- **生產者-消費者**（有限緩衝區）：`mutex=1`、`empty=n`、`full=0`
- 讀者-寫者、哲學家用餐（可能死結）

## 觀念 5：死結（Deadlock）

### 5.1 死結四個必要條件（缺一不可）
1. **互斥（Mutual Exclusion）**
2. **持有並等待（Hold and Wait）**
3. **不可搶占（No Preemption）**
4. **循環等待（Circular Wait）**

### 5.2 處理方式
| 方式 | 作法 |
|---|---|
| **預防（Prevention）** | 破壞四條件之一（例：資源編號、依序申請 → 破壞循環等待） |
| **避免（Avoidance）** | 每次配置前檢查是否仍處於**安全狀態** → **銀行家演算法** |
| **偵測與復原** | 允許死結發生，定期偵測，再終止行程或搶回資源 |
| **忽略（鴕鳥法）** | 多數一般 OS（Windows、Linux）採用 |

> **安全狀態一定沒有死結；不安全狀態不一定死結，但可能發生。**

### 5.3 銀行家演算法步驟
1. Need = Max − Allocation
2. 找一個 Need ≤ Available 的行程，假設它執行完，釋放資源：Available += Allocation
3. 重複直到全部完成 → 安全；找不到 → 不安全

### 5.4 不會死結的最少資源數
n 個行程，每個最多需要 m 個同類資源：最少需要 **n × (m − 1) + 1** 個資源。

## 觀念 6：記憶體管理與分頁

### 6.1 連續配置策略
- **First Fit**：第一個夠大的洞（最快）
- **Best Fit**：最小但夠大的洞（留下最小碎片）
- **Worst Fit**：最大的洞

### 6.2 碎片
| 碎片 | 定義 | 發生在 |
|---|---|---|
| **內部碎片** | 配給的空間比需要的大，**區塊內**浪費 | **分頁**（最後一頁用不滿） |
| **外部碎片** | 總空間夠，但**不連續**無法配置 | 連續配置、**分段** |
| 解法 | 壓縮（compaction）、分頁 | |

### 6.3 分頁（Paging）
- 邏輯記憶體切成固定大小的 **頁（Page）**，實體記憶體切成同大小的 **頁框（Frame）**。
- 邏輯位址 = **頁碼 p | 位移 d**；頁大小 2ⁿ → 位移占 **n 位元**。
- 實體位址 = 頁框號 × 頁大小 + 位移。
- **分頁表項目數** = 邏輯位址空間 / 頁大小。

### 6.4 TLB（轉譯後備緩衝區）
分頁表放記憶體，每次存取要兩次記憶體 → 用 TLB 快取頁表項目。
$$\text{EAT} = h × (T_{TLB} + T_m) + (1 - h) × (T_{TLB} + 2T_m)$$

## 觀念 7：虛擬記憶體與頁面置換

### 7.1 名詞
- **需求分頁（Demand Paging）**：用到才載入。
- **分頁錯誤（Page Fault）**：要存取的頁不在記憶體 → 由 OS 從磁碟載入。
- **輾轉現象（Thrashing）**：頁框太少，行程大部分時間都在換頁，CPU 使用率驟降。解法：工作集模型、控制分頁錯誤頻率、降低多元程式程度。

### 7.2 置換演算法
| 演算法 | 作法 | 備註 |
|---|---|---|
| **FIFO** | 換掉最早進來的 | 會有 **Belady 異常**（頁框變多、錯誤反而增加） |
| **OPT**（最佳） | 換掉**未來最久不會用到**的 | 錯誤最少，但無法實作，用來當基準 |
| **LRU** | 換掉**過去最久沒用到**的 | 效果接近 OPT，不會有 Belady 異常 |

### 範例：參考串 `1 2 3 4 1 2 5 1 2 3 4 5`，3 個頁框

**FIFO（9 次錯誤）**
| 參考 | 1 | 2 | 3 | 4 | 1 | 2 | 5 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 框 | 1 | 1,2 | 1,2,3 | 2,3,4 | 3,4,1 | 4,1,2 | 1,2,5 | — | — | 2,5,3 | 5,3,4 | — |
| 錯誤 | F | F | F | F | F | F | F | | | F | F | |

（以 4 個頁框跑 FIFO 反而有 10 次錯誤 → Belady 異常）

## 觀念 8：磁碟排程

| 演算法 | 作法 |
|---|---|
| FCFS | 依請求順序 |
| **SSTF** | 每次選**離目前磁頭最近**的（可能飢餓） |
| **SCAN**（電梯） | 往一個方向走到底，再折返 |
| **C-SCAN** | 往一個方向走到底，**直接跳回起點**再同方向服務（等待時間較平均） |
| LOOK / C-LOOK | 同 SCAN / C-SCAN，但只走到最後一個請求就折返 |

## 📝 本章重點速記

- 系統呼叫：user → kernel；特權指令只在核心模式
- Waiting 完成 → Ready（不是 Running）
- 執行緒獨有：Stack、暫存器、PC
- n 次 fork → 2ⁿ 個行程
- SJF 平均等待最小、會飢餓（老化解決）；FCFS 護航效應；RR q 太大 → FCFS
- 臨界區三條件：互斥、進行、有限等待
- 死結四條件：互斥、持有等待、不可搶占、循環等待；銀行家 = 避免
- 不死結最少資源：n(m−1)+1
- 分頁 → 內部碎片；分段 → 外部碎片
- FIFO 有 Belady 異常；OPT 最少；LRU 接近 OPT
- SSTF 最近優先；SCAN 電梯
