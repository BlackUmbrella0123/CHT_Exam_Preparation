## 觀念 1：資料庫系統基本概念

### 1.1 DBMS 的優點（相對於檔案系統）
減少資料**重複**、避免**不一致**、資料**共享**、安全控管、完整性限制、並行控制、備份與復原。

### 1.2 ANSI/SPARC 三層架構
| 層級 | 說明 | 使用者 |
|---|---|---|
| **外部層（External）** | 個別使用者看到的**視界（View）** | 一般使用者 |
| **概念層（Conceptual）** | 整個資料庫的邏輯結構（表格、關聯、限制） | DBA、設計者 |
| **內部層（Internal）** | 實際儲存方式（檔案、索引） | 系統 |

### 1.3 資料獨立性
- **邏輯資料獨立**：修改**概念層**時，不影響外部層（應用程式）。
- **實體資料獨立**：修改**內部層**（如換儲存結構、加索引）時，不影響概念層。
> 邏輯資料獨立性較難達成。

### 1.4 SQL 語言分類
| 類別 | 指令 |
|---|---|
| **DDL**（定義） | CREATE、ALTER、DROP、TRUNCATE |
| **DML**（操作） | SELECT、INSERT、UPDATE、DELETE |
| **DCL**（控制） | GRANT、REVOKE |
| **TCL**（交易） | COMMIT、ROLLBACK、SAVEPOINT |

## 觀念 2：ER 模型與關聯模型、鍵與完整性

### 2.1 ER 模型
- **實體（Entity）**：矩形；**屬性**：橢圓（底線 = 鍵屬性，雙橢圓 = 多值屬性，虛線 = 衍生屬性）；**關係**：菱形。
- 基數：1:1、1:N、M:N。**M:N 關係轉成表格時，需要另建一張關聯表**。
- 弱實體：雙矩形，依附於擁有者實體才能識別。

### 2.2 關聯模型名詞
| 名詞 | 對應 |
|---|---|
| 關聯（Relation） | 表格 |
| 值組（Tuple） | 列 / 記錄 |
| 屬性（Attribute） | 欄 |
| **基數（Cardinality）** | **列數** |
| **分支度（Degree）** | **欄數** |
| 定義域（Domain） | 屬性可能值的集合 |

### 2.3 鍵（Key）
| 鍵 | 定義 |
|---|---|
| **超鍵 Super Key** | 能唯一識別每一列的屬性集合（可能有多餘屬性） |
| **候選鍵 Candidate Key** | **最小**的超鍵（不能再拿掉任何屬性） |
| **主鍵 Primary Key** | 從候選鍵中選出一個；**不可為 NULL、不可重複** |
| 替代鍵 Alternate Key | 未被選為主鍵的候選鍵 |
| **外來鍵 Foreign Key** | 參考另一表格主鍵的屬性 |

### 2.4 完整性限制
- **實體完整性**：主鍵**不可為 NULL**。
- **參考完整性**：外來鍵的值必須是**被參考表中存在的主鍵值**，或為 NULL。
- 定義域完整性：值必須在允許範圍內。

## 觀念 3：關聯代數

| 運算 | 符號 | 作用 | 結果 |
|---|---|---|---|
| **選擇 Selection** | σ | 挑出符合條件的**列** | 水平切割 |
| **投影 Projection** | π | 挑出指定的**欄**（會去除重複） | 垂直切割 |
| 聯集 | ∪ | 兩表所有列 | 需**相容** |
| 差集 | − | 在 R 不在 S | 需相容 |
| 交集 | ∩ | 同時在 R 與 S | 需相容 |
| **卡氏積** | × | R 每列配 S 每列 | 列數 m × n、欄數相加 |
| **合併 Join** | ⋈ | 依條件結合 | 自然合併會合併同名欄位 |
| 除法 | ÷ | 「所有」型查詢 | 例：修了**所有**課的學生 |

> **相容（Union Compatible）**：兩表欄數相同，且對應欄位定義域相同。

## 觀念 4：SQL 查詢

### 4.1 語法結構與**執行順序**
```sql
SELECT   欄位, 聚合函數        -- ⑤
FROM     表格                  -- ①
WHERE    列的條件              -- ②
GROUP BY 分組欄位              -- ③
HAVING   分組後的條件          -- ④
ORDER BY 欄位 ASC|DESC;        -- ⑥
```
- **WHERE 篩選「列」，不能用聚合函數；HAVING 篩選「群組」，可以用聚合函數。**
- 聚合函數：`COUNT`、`SUM`、`AVG`、`MAX`、`MIN`。`COUNT(*)` 算所有列；`COUNT(欄位)` **不算 NULL**。
- `DISTINCT` 去除重複；`LIKE 'A%'`（% 任意多字元，_ 單一字元）；`BETWEEN a AND b`（**包含**兩端）；`IN (...)`；`IS NULL`。

### 4.2 JOIN
| 類型 | 結果 |
|---|---|
| INNER JOIN | 只保留兩邊都對得上的列 |
| LEFT JOIN | 保留左表全部，右表對不上補 NULL |
| RIGHT JOIN | 保留右表全部 |
| FULL OUTER JOIN | 兩邊全保留 |

### 4.3 DELETE / TRUNCATE / DROP
- `DELETE FROM t WHERE …`：刪除符合條件的列（DML，可 ROLLBACK）
- `TRUNCATE TABLE t`：清空所有列，保留表結構
- `DROP TABLE t`：連表結構一起刪除

## 觀念 5：正規化

### 5.1 為什麼要正規化？避免三種異常
- **新增異常**：還沒有某資料就無法新增另一筆（例：沒學生選的課無法新增）
- **刪除異常**：刪除一筆資料時，連帶遺失其他資訊
- **更新異常**：同一資料重複存多處，更新時漏改造成不一致

### 5.2 各正規化形式
| 正規化 | 條件 | 要消除的 |
|---|---|---|
| **1NF** | 每個欄位都是**單一值（atomic）**，沒有重複群組 | 多值屬性 |
| **2NF** | 1NF + **無部分相依**（非鍵屬性必須完全相依於**整個**主鍵） | 部分功能相依 |
| **3NF** | 2NF + **無遞移相依**（非鍵屬性不能相依於另一個非鍵屬性） | 遞移相依 |
| **BCNF** | 每個決定因子（X → Y 的 X）都必須是**候選鍵** | 更嚴格的 3NF |
| 4NF | BCNF + 無多值相依 | |
| 5NF | 無合併相依 | |

> 口訣：**「1NF 單值、2NF 不部分、3NF 不遞移、BCNF 決定因子皆為鍵」**
> 註：**只有一個屬性當主鍵的表，若符合 1NF 就一定符合 2NF**（不可能有部分相依）。

## 觀念 6：交易與並行控制

### 6.1 交易 ACID
| 特性 | 意義 | 負責機制 |
|---|---|---|
| **A 單元性 Atomicity** | 全部完成或全部不做 | 復原（Undo / Log） |
| **C 一致性 Consistency** | 交易前後資料都滿足限制 | 完整性限制、程式邏輯 |
| **I 隔離性 Isolation** | 並行交易互不干擾 | 並行控制（鎖定） |
| **D 永久性 Durability** | 提交（COMMIT）後的結果永久保存 | 日誌、備份、Redo |

### 6.2 並行問題
| 問題 | 說明 |
|---|---|
| **遺失更新 Lost Update** | 兩交易同時改同一筆，其中一個的修改被覆蓋 |
| **髒讀 Dirty Read** | 讀到別人**尚未 COMMIT** 的資料 |
| **不可重複讀 Non-repeatable Read** | 同一交易內兩次讀同一筆，值不同（被別人改了） |
| **幻影讀 Phantom Read** | 同一條件兩次查詢，**筆數**不同（被別人新增/刪除） |

### 6.3 隔離等級（由低到高）
| 等級 | 髒讀 | 不可重複讀 | 幻影讀 |
|---|---|---|---|
| Read Uncommitted | 可能 | 可能 | 可能 |
| Read Committed | ✗ | 可能 | 可能 |
| Repeatable Read | ✗ | ✗ | 可能 |
| **Serializable** | ✗ | ✗ | ✗ |

### 6.4 鎖定
- **共享鎖（S，讀鎖）**：多個交易可同時持有。
- **互斥鎖（X，寫鎖）**：只能一個交易持有。
- **兩階段鎖定（2PL）**：成長階段只能加鎖、縮減階段只能解鎖 → 保證**可序列化**，但**仍可能死結**。

## 觀念 7：索引與 NoSQL

### 7.1 索引
- 常用 **B+ 樹**：所有資料在葉節點、葉節點串成鏈結串列 → 適合**範圍查詢**。
- 雜湊索引：適合**等值查詢**，不適合範圍查詢。
- 索引加快查詢，但**會拖慢新增、修改、刪除**，也占空間。

### 7.2 NoSQL 類型
| 類型 | 代表 | 適用 |
|---|---|---|
| **鍵值 Key-Value** | Redis | 快取、Session |
| **文件 Document** | **MongoDB** | JSON 半結構化資料 |
| **欄族 Column-Family** | Cassandra、HBase | 大量寫入、時序資料 |
| **圖形 Graph** | Neo4j | 社群網路、推薦關係 |

### 7.3 CAP 定理
分散式系統**無法同時**滿足：**C 一致性、A 可用性、P 分區容忍性**，最多只能三選二（實務上 P 必須保留，因此在 C 與 A 之間取捨）。
NoSQL 常採 **BASE**（Basically Available、Soft state、Eventually consistent，最終一致性）。

**你的作答：**
```sql

```

<details>
<summary>▶ 參考答案與評分重點</summary>

```sql
-- (1) 三表 JOIN（4 分）
SELECT S.name
FROM Student S
JOIN Enroll E ON S.sid = E.sid
JOIN Course C ON E.cid = C.cid
WHERE C.title = '資料庫' AND E.score >= 80;

-- (2) GROUP BY + HAVING + ORDER BY（4 分）
SELECT S.dept, AVG(E.score) AS avg_score
FROM Student S
JOIN Enroll E ON S.sid = E.sid
GROUP BY S.dept
HAVING AVG(E.score) > 75
ORDER BY avg_score DESC;

-- (3) 三種寫法皆可（4 分）
SELECT name FROM Student
WHERE sid NOT IN (SELECT sid FROM Enroll);

SELECT S.name FROM Student S
WHERE NOT EXISTS (SELECT * FROM Enroll E WHERE E.sid = S.sid);

SELECT S.name FROM Student S
LEFT JOIN Enroll E ON S.sid = E.sid
WHERE E.sid IS NULL;
```

## 📝 本章重點速記

- 三層架構：外部 / 概念 / 內部；改內部層不影響 = 實體獨立
- Degree = 欄數；Cardinality = 列數
- 候選鍵 = 最小超鍵；主鍵不可 NULL（實體完整性）；外來鍵（參考完整性）
- σ 選列、π 選欄；R×S 列數相乘、欄數相加；「所有」→ 除法
- SQL 執行順序：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
- WHERE 不能放聚合函數；COUNT(欄位) 不計 NULL；BETWEEN 含端點
- 1NF 單值、2NF 無部分相依、3NF 無遞移相依、BCNF 決定因子皆為候選鍵
- ACID；髒讀 = 讀到未提交；Serializable 最高隔離；2PL 保證可序列化但可能死結
- B+ 樹索引；MongoDB 文件型；CAP 三選二
